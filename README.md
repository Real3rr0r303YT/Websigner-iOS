# WebSigner for iOS

> An open-source direct web installer and signer for iOS. Install apps over the air from Safari, with no computer, cables or App Store.

## Features

- **One-tap OTA install:** uses Apple's native `itms-services` over-the-air installation.
- **Web Signer:** drop an IPA, `.p12` and provisioning profile onto the page, then sign and install it right from Safari.
- **Sign your own IPAs:** bring your own certificate and provisioning profile.
- **Anti-revoke friendly:** includes a NextDNS guide for blocking Apple's revocation checks.
- **Free and open source:** licensed under GPL-3.0.

## Installing the app (users)

1. Open the [landing page](https://real3rr0r303yt.github.io/Websigner-iOS/) in **Safari** on your iPhone or iPad.
2. *(Recommended)* Set up the anti-revoke DNS first. See [below](#dns--anti-revoke-guide).
3. Tap **Install App** and confirm the prompt.
4. Go to **Settings → General → VPN & Device Management**, select the developer certificate and tap **Trust**.
5. If asked, turn on **Developer Mode** in **Settings → Privacy & Security**.

> OTA installs only work in Safari. Chrome, Firefox and in-app browsers will not trigger the install.

## Web Signer (sign any IPA in the browser)

The **Web Signer** section on the landing page lets you sign any IPA with your own certificate and install it straight from Safari, much like eSign, but using your own GitHub repository as the backend.

### How it works

1. You drop an `.ipa`, a `.p12` certificate (plus its password) and a `.mobileprovision` onto the page.
2. **Your browser checks everything locally:**
   - the IPA layout, Simulator builds and App Store (FairPlay) encryption
   - the certificate password and expiry
   - the profile type and expiry
   - whether the certificate is in the profile
   - App ID vs. bundle ID, and optionally your device's UDID
3. When you press **Sign & prepare install**:
   - The `.p12`, its password and the profile are **encrypted in the browser** with your repository's public key and stored as temporary Actions secrets.
   - The IPA is encrypted with a one-time AES-256 key and committed to a temporary `websigner-upload/<id>` branch.
   - `.github/workflows/sign.yml` decrypts everything on the runner and signs the app with [zsign](https://github.com/zhlynn/zsign). It then validates the result with `tools/check_ipa.py`, uploads it to the `websigner` release and commits `signed/<id>.plist`.
   - Once GitHub Pages serves the manifest, the page shows an **Install** button and a QR code that links to `…/?install=<id>`, so you can install on your iPhone.
   - The temporary secrets and the upload branch are then deleted.

### Setup (one-time)

1. **Fork** this repository. In the fork:
   - Open the **Actions** tab and enable workflows. Forks start with workflows disabled.
   - Enable **GitHub Pages** (see [Enable GitHub Pages](#1-enable-github-pages)).
2. Create a [fine-grained personal access token](https://github.com/settings/personal-access-tokens/new):
   - **Repository access:** only your fork
   - **Repository permissions:**
     - **Contents:** Read and write
     - **Actions:** Read and write
     - **Secrets:** Read and write
     - **Pages:** Read and write (optional: lets the page trigger a Pages rebuild if publishing is slow)
3. Open your fork's landing page, scroll to **Web Signer** and enter `owner/repository` and the token. The repository is filled in automatically on `*.github.io`.

### Good to know

- Only one signing job can run at a time. The page refuses to start while another one is running.
- Use an **Ad Hoc**, **Development** or **Enterprise** profile. App Store profiles can't be installed directly.
- Maximum IPA size is about 95 MB, because the GitHub API accepts at most 100 MB per upload.
- **Signed IPAs are public.** iOS has to download them without logging in, so anyone with the link can download them from the `websigner` release. Delete old assets from that release when you no longer need them.
- If you close the tab while a job is running, the temporary secrets stay in the repository until the next signing overwrites them. You can also delete them under **Settings → Secrets and variables → Actions**.
- Whether Apple has revoked your certificate can't be checked from the browser. A revoked certificate signs fine, but iOS refuses to install the app.
- App Store downloads are FairPlay-encrypted. They install, but crash on launch. Use decrypted IPAs.

## Deploying your own copy (maintainers)

### 1. Enable GitHub Pages

1. Go to **Settings → Pages**.
2. Under **Build and deployment**, choose **Deploy from a branch**, then select your branch and `/ (root)`.
3. Your site will be live at `https://<username>.github.io/<repo>/`. Write `<repo>` exactly as GitHub shows it, including upper and lower case (this repository: `Websigner-iOS`).

### 2. Add your signing secrets (one-time)

iOS only installs an app over the air if it's signed for the device, so you need a paid Apple Developer account.

1. In the [Apple Developer portal](https://developer.apple.com/account/resources/certificates/list), create an **Apple Distribution** certificate. Export it from Keychain Access as a `.p12` file with a password.
2. Register the UDIDs of every device that should install the app. Enterprise (In-House) accounts can skip this.
3. Create an **Ad Hoc** (or **In-House**) provisioning profile for the App ID `com.real3rr0r303yt.websigner`, using that certificate and those devices. Download the `.mobileprovision`.
4. Add these secrets under **Settings → Secrets and variables → Actions**:

| Secret | Value |
| --- | --- |
| `BUILD_CERTIFICATE_BASE64` | Output of `base64 -i cert.p12` (macOS) or `base64 -w0 cert.p12` (Linux) |
| `P12_PASSWORD` | The `.p12` password |
| `BUILD_PROVISION_PROFILE_BASE64` | Output of `base64 -i profile.mobileprovision` (macOS) or `base64 -w0 profile.mobileprovision` (Linux) |

The workflow reads the bundle ID, team ID and export method from the profile, so they always match the signed app.

### 3. Build and publish v1.2.0

1. Go to **Actions → Build IPA → Run workflow**, enter `v1.2.0` and run it.
2. The workflow:
   - generates the Xcode project from `app/project.yml` with XcodeGen,
   - archives and signs the app for real devices (arm64),
   - exports `WebSigner.ipa` with the required `Payload/WebSigner.app` layout,
   - validates it with `tools/check_ipa.py`,
   - creates the GitHub Release `v1.2.0` and uploads `WebSigner.ipa` to it,
   - regenerates `manifest.plist` (`bundle-identifier`, `bundle-version` `1.2.0`, `kind` `software`, `title`, and the direct `.ipa` download URL) and commits it.
3. When GitHub Pages has redeployed, open the landing page in Safari and tap **Install App**.

Pushing a tag such as `v1.2.0` runs the same workflow.

### Using your own app or an existing IPA

- **Your own app:** `app/` contains a minimal SwiftUI starter app. Replace the code in `app/Sources/` with your own, or extend `app/project.yml` ([XcodeGen spec](https://github.com/yonaskolb/XcodeGen/blob/master/Docs/ProjectSpec.md)).
- **Building locally:** run `cd app && xcodegen generate`, open `WebSigner.xcodeproj` and choose **Any iOS Device (arm64)**. Then choose **Product → Archive → Distribute App → Release Testing** (Ad Hoc) or **Enterprise**. Don't choose App Store Connect.
- **An IPA built elsewhere:** create a Release (e.g. `v1.2.0`) and attach the `.ipa`. The **OTA release** workflow validates it and regenerates `manifest.plist`. You can also generate the manifest locally:

```bash
python3 tools/check_ipa.py WebSigner.ipa --write-manifest manifest.plist \
  --ipa-url https://github.com/<username>/<repo>/releases/download/v1.2.0/WebSigner.ipa \
  --display-image https://<username>.github.io/<repo>/assets/icon-57.png \
  --full-size-image https://<username>.github.io/<repo>/assets/icon-512.png
```

**Packaging an already-signed `.app` by hand:**

```bash
mkdir Payload
cp -R WebSigner.app Payload/
zip -qry WebSigner.ipa Payload   # -y keeps framework symlinks intact
```

The archive's top level must be `Payload/`. Don't edit anything inside the `.app` after signing, not even `Info.plist`, or the signature breaks.

**Check any IPA before publishing:**

```bash
python3 tools/check_ipa.py WebSigner.ipa --udid <your-device-UDID>
```

This checks the archive layout, arm64 binary, code signature, profile type and expiry, App ID vs. bundle ID, extension bundle IDs, and whether your UDID is in the profile.

### How the Install button works

When served over HTTPS, `index.html` builds the install link from its own address:

```
itms-services://?action=download-manifest&url=<URL-encoded HTTPS URL of manifest.plist next to the page>
```

The link therefore always points at the right `manifest.plist`, even in a fork or under a renamed repository. The static `href` on `#install-btn` is only a fallback for when the page isn't served over HTTPS.

**Requirements for OTA installs:**

- The manifest **and** the IPA must be served over **HTTPS** with a valid, trusted certificate. GitHub Pages and GitHub Releases both qualify.
- The IPA must be signed with a certificate and provisioning profile valid for the target device (enterprise, ad-hoc with the device's UDID, or developer).

### Troubleshooting "Unable to install … cannot be installed at this time"

Run `python3 tools/check_ipa.py WebSigner.ipa --udid <UDID>` first. It catches most of these.

| Cause | Fix |
| --- | --- |
| `software-package` URL returns 404 (e.g. no Release yet, or the asset has a different name) | Publish a Release with the `.ipa` and let the workflow regenerate the manifest. Open the URL in a browser to confirm it downloads. |
| Manifest or icon URLs use the wrong letter case for the repository name (e.g. `WebSigner-iOS` instead of `Websigner-iOS`) | Use the repository name exactly as GitHub shows it. The Install button now finds the manifest automatically. |
| Manifest or IPA not on HTTPS, or Pages not enabled | Enable Pages (step 1) and open the manifest URL in Safari. It must load without a certificate warning. |
| Unsigned, Simulator or App Store-signed IPA | Re-export as Ad Hoc, Development or Enterprise (see *Add your signing secrets*). |
| Device UDID not in the Ad Hoc profile | Register the UDID, regenerate the profile, re-sign. |
| `bundle-identifier` in the manifest ≠ `CFBundleIdentifier` in the IPA | Regenerate the manifest from the IPA (run **Build IPA** or **OTA release**). |
| Signing certificate expired or revoked by Apple | Re-sign with a valid certificate. DNS blocking can't revive a certificate that's already revoked. |
| App with the same bundle ID already installed from a different team (e.g. the App Store) | Delete the existing app first, or use a different bundle ID. |
| Device iOS is older than the app's `MinimumOSVersion` | Update iOS or lower the deployment target. |
| Opened in Chrome/Firefox or an in-app browser | Use Safari. |

To find a device's UDID, connect it to a Mac and click the serial number in Finder, or use a UDID-lookup profile site.

## DNS / Anti-Revoke Guide

iOS checks with Apple whether an app's signing certificate is still valid. If Apple has revoked it, the app will no longer open. Blocking those checks via DNS helps keep installed apps working.

1. Create a free account at [my.nextdns.io](https://my.nextdns.io/signup).
2. In the **Denylist** tab, add:
   - `ppq.apple.com` **(required)**
   - *Optional, stronger, may affect some Apple services:* `ocsp.apple.com`, `ocsp2.apple.com`, `crl.apple.com`, `valid.apple.com`
3. On your device, open [apple.nextdns.io](https://apple.nextdns.io) in Safari, enter your configuration ID and download the profile.
4. Install it via **Settings → General → VPN & Device Management**.
5. Check that it's working at [test.nextdns.io](https://test.nextdns.io). It should report `"status": "ok"`.

> ⚠️ Keep the profile enabled at all times, including on cellular. DNS blocking lowers the risk of revocation but cannot guarantee it won't happen.
